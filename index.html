HOW I WORK

Build it. Test it. Improve it.

I don't like treating technology as a collection of tools to memorize.

When something interests me, I want to know why it works, not just how to make it run. That usually means breaking the problem down, writing some code, working with the data, testing assumptions, and learning from whatever breaks along the way.

I'm still developing my craft, and I think that's part of the point.
